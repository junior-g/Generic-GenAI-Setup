## Migrations

| | |
|---|---|
| Where they live | `path` |
| Naming | |
| Run with | `<command>` |
| Reversible? | <are down-migrations written, and are they tested> |
| Applied automatically on deploy? | |
| Zero-downtime requirement | |

Rules:

1. **Expand, migrate, contract.** Add the new shape, dual-write or backfill, migrate readers, then remove the
   old shape in a separate approved step. Never contract first.
2. **A migration is tested against realistic data volume**, or its unverified limits are stated as a residual
   risk. A migration that is fast on ten rows and locks the table on ten million is not tested.
3. **Backfills are idempotent, batched, and resumable.** A backfill that cannot be re-run from the middle
   will be re-run from the start.
4. **Destructive migrations need explicit approval every time** (**F6**).
